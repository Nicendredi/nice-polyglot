# Contract: Config File Schema

**Branch**: `001-polyglot-config-extension` | **Date**: 2026-04-25

This contract defines the YAML schema for all three `nice-polyglot-config.yml` layers.
All three layers share the same schema; which fields are authoritative varies by layer
(see data-model.md for merge rules).

---

## Schema

```yaml
# nice-polyglot-config.yml
# Schema version: "1.0"
# All fields are optional. Missing fields fall through to the lower-precedence layer.

schema_version: "1.0"

# Accepted language codes for shared file-output categories.
# AUTHORITATIVE at project layer.
# Extension layer may also set this to establish shared defaults across all projects
# in a shared `.specify/` root. Not shipped by the extension itself.
# User layer: this field is IGNORED (FR-010).
# Rules:
#   - Values must be ISO 639-1 two-letter codes (e.g., "en", "fr", "es")
#   - "en" is always implicitly present; add it explicitly to be clear
#   - Unrecognized codes are silently ignored
#   - An empty list is treated as ["en"]
accepted_languages:
  - en       # English — always the fallback
  - fr       # Example: French

language_settings:
  # Conversational language for agent-to-user interaction.
  # NOT constrained by accepted_languages.
  # Any ISO 639-1 code accepted.
  interactions: en

  # Language for SpecKit artifact files (spec.md, plan.md, tasks.md, etc.)
  # Must be in accepted_languages or falls back to "en".
  artifacts: en

  # Language for user-facing documentation generated by agents.
  # Must be in accepted_languages or falls back to "en".
  documentation: en

  # Language for generated source code.
  # Must be in accepted_languages or falls back to "en".
  code: en

  # Language for comments inside generated source code.
  # Must be in accepted_languages or falls back to "en".
  code-comments: en

  # Language for log output messages generated by agents.
  # Must be in accepted_languages or falls back to "en".
  log-messages: en

  # Language for internal/developer-facing documentation.
  # Must be in accepted_languages or falls back to "en".
  internal-docs: en

  # Language for git commit messages generated by agents.
  # Must be in accepted_languages or falls back to "en".
  commit-messages: en
```

---

## Per-Layer Field Authority

| Field | Extension layer | Project layer | User layer |
|---|---|---|---|
| `schema_version` | Sets default | Overrides | Overrides |
| `accepted_languages` | Sets shared defaults (optional) | **Authoritative** — overrides extension | **Ignored** |
| `language_settings.*` | Sets shared defaults (optional) | Overrides extension | Overrides extension+project |

---

## Validation Constraints

> **Design constraint** (not a spec FR): `schema_version` handling is an implementation-level forward-compatibility mechanism. It is intentionally not captured as a functional requirement because it has no user-visible behavioral effect in v1.0. The behavior below is the authoritative design decision for implementers.

| Field | Constraint |
|---|---|
| `schema_version` | If present, must be `"1.0"`. Unknown versions: log warning, continue. |
| `accepted_languages` items | Must match `/^[a-z]{2}$/`. Invalid items silently dropped. |
| `accepted_languages` (result) | Must contain at least `"en"` after validation. |
| `language_settings.*` (shared) | Must be in resolved `accepted_languages` or falls back to `"en"`. |
| `language_settings.interactions` | Must match `/^[a-z]{2}$/` or falls back to `"en"`. No other constraint. |

## File Locations

| Layer | Path (relative to `.specify` root) | Notes |
|---|---|---|
| Extension layer | `extensions/nice-polyglot/nice-polyglot-config.yml` | Optional; user-created from `config-template.yml` |
| Project override | `overrides/nice-polyglot-config.yml` | Optional; user-created from `config-template.yml` |
| User override | `.nice-polyglot/{user}-config.yml` | Optional; user-created from `config-template.yml` |

`{user}` derivation: `git config user.email` with `@` → `-at-`, `.` → `-`, lowercased.
Fallback: `$env:USERNAME` / `$env:USER` / `unknown`.

---

## Error Handling

If a config file exists but cannot be read or parsed:
- The file is skipped entirely (all fields treated as absent for that layer)
- A warning is surfaced to the user: `[nice-polyglot] WARNING: Could not read {path}. Using settings from lower-precedence layers.`
- The workflow continues with the next valid lower-precedence layer values
