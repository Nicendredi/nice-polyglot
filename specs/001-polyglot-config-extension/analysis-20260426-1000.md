## Next Actions

### Before `/speckit.implement`

**I1 (CRITICAL) must be resolved.** The tasks.md T009 algorithm description is internally inconsistent: its step ordering makes the primary project-configuration use case fail. Without this fix, the core feature (a project maintainer setting `accepted_languages` and `language_settings` in the same config layer) is broken by specification.

**Recommended actions:**

1. **Fix T009 algorithm** — Rewrite steps 2c–2f to: (c) validate V-002 on `accepted_languages` format; (d) tentatively apply the layer's `accepted_languages` (if present) to the working policy; (e) validate V-004 (`interactions`); (f) validate V-003 against the now-updated working `accepted_languages`; (g) commit all remaining language_settings values. Run `/speckit.tasks` after fixing if any other task descriptions derived from T009 need updates.
2. **Fix T009 + I2** — Add the "always ensure `en` in `accepted_languages`" enforcement step after each layer replacement.
3. **Fix I3** — Update config-schema.md `accepted_languages` comment to match V-002 (layer invalid, not silent ignore).
4. **Address U1 / A2** — Add bash scaffold acceptance criteria to T006 (shebang, commented algorithm, "not yet implemented" exit). Add `scripts/bash/resolve-language-policy.sh` to T020 zip-contents list (U2).
5. **Address A1 (LOW)** — Add deferral note to T006 and plan's Constitution Check clarifying that `common.sh` integration and Principle III compliance for bash are scoped to a future feature.

**I4 (LOW)** may be addressed as part of the above edits or deferred; it does not block implementation.
