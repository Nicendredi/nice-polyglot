# nice-polyglot

[Version française plus bas](#version-française)

---

## English

**nice-polyglot** is a SpecKit Community Extension (SpecKit ≥ 0.5.1) that configures the
language used by SpecKit agents for each of their 8 output categories:

| Category | What it controls |
|---|---|
| `interactions` | Agent-to-user conversational language (unconstrained) |
| `artifacts` | SpecKit artifact files (spec.md, plan.md, tasks.md, …) |
| `documentation` | User-facing documentation generated by agents |
| `code` | Generated source code |
| `code-comments` | Comments inside generated code |
| `log-messages` | Log output messages generated by agents |
| `internal-docs` | Internal / developer-facing documentation |
| `commit-messages` | Git commit messages generated by agents |

Language settings are resolved from up to **three optional config layers** in ascending
precedence order — every layer is user-created from `config-template.yml`, so updating
the extension never overwrites your configuration:

1. **Extension layer** — `.specify/extensions/nice-polyglot/nice-polyglot-config.yml`
2. **Project layer** — `.specify/overrides/nice-polyglot-config.yml` *(authoritative for `accepted_languages`)*
3. **User layer** — `.specify/.nice-polyglot/{user}-config.yml` *(personal preferences)*

When no config files are present the extension uses hardcoded defaults (all categories `en`).

### Quick Installation

```bash
# Install from a local zip
specify extension add nice-polyglot --from ./nice-polyglot-1.0.0.zip

# Or install from the community catalog (after adding catalog-entry.json to your catalog)
specify extension add nice-polyglot
```

Verify installation:

```bash
specify extension list
# Output: ✓ Nice Polyglot (v1.0.0)
```

### Configuration Overview

Copy `config-template.yml` to whichever layer path you need and uncomment the fields you
want to set. The three layer paths are:

| Layer | Path (relative to `.specify/` root) |
|---|---|
| Extension | `extensions/nice-polyglot/nice-polyglot-config.yml` |
| Project | `overrides/nice-polyglot-config.yml` |
| User | `.nice-polyglot/{user}-config.yml` |

`{user}` is derived from `git config user.email` (sanitised) or `$env:USERNAME` / `$USER` as
fallbacks.

The `accepted_languages` field is **authoritative at the project layer** — it controls which
languages are valid for shared file-output categories. The `interactions` category is the only
one that is not constrained by `accepted_languages`.

All fields are optional. Missing fields fall through to the next lower layer.

## Version française

<a id="version-française"></a>

**nice-polyglot** est une extension communautaire SpecKit (SpecKit ≥ 0.5.1) qui configure
la langue utilisée par les agents SpecKit pour chacune de leurs 8 catégories de sortie :

| Catégorie | Ce qu'elle contrôle |
|---|---|
| `interactions` | Langue des échanges entre l'agent et l'utilisateur (non contrainte) |
| `artifacts` | Fichiers d'artefacts SpecKit (spec.md, plan.md, tasks.md, …) |
| `documentation` | Documentation destinée aux utilisateurs, générée par les agents |
| `code` | Code source généré |
| `code-comments` | Commentaires dans le code généré |
| `log-messages` | Messages de journalisation générés par les agents |
| `internal-docs` | Documentation interne / à destination des développeurs |
| `commit-messages` | Messages de commit Git générés par les agents |

Les paramètres de langue sont résolus depuis jusqu'à **trois couches de configuration
optionnelles** par ordre de priorité croissante — chaque couche est créée par l'utilisateur
à partir de `config-template.yml`, ce qui garantit que la mise à jour de l'extension
n'écrase jamais votre configuration :

1. **Couche extension** — `.specify/extensions/nice-polyglot/nice-polyglot-config.yml`
2. **Couche projet** — `.specify/overrides/nice-polyglot-config.yml` *(fait autorité pour `accepted_languages`)*
3. **Couche utilisateur** — `.specify/.nice-polyglot/{user}-config.yml` *(préférences personnelles)*

En l'absence de tout fichier de configuration, l'extension utilise les valeurs par défaut
codées en dur (toutes les catégories à `en`).

### Installation rapide

```bash
# Installer depuis un zip local
specify extension add nice-polyglot --from ./nice-polyglot-1.0.0.zip

# Ou installer depuis le catalogue communautaire (après avoir ajouté catalog-entry.json à votre catalogue)
specify extension add nice-polyglot
```

Vérifier l'installation :

```bash
specify extension list
# Résultat : ✓ Nice Polyglot (v1.0.0)
```

### Aperçu de la configuration

Copiez `config-template.yml` vers le chemin de la couche souhaitée et décommentez les
champs à configurer. Les trois chemins de couche sont :

| Couche | Chemin (relatif à la racine `.specify/`) |
|---|---|
| Extension | `extensions/nice-polyglot/nice-polyglot-config.yml` |
| Projet | `overrides/nice-polyglot-config.yml` |
| Utilisateur | `.nice-polyglot/{user}-config.yml` |

`{user}` est dérivé de `git config user.email` (assaini) ou de `$env:USERNAME` / `$USER`
en cas de repli.

Le champ `accepted_languages` fait **autorité au niveau de la couche projet** — il contrôle
les langues valides pour les catégories de sortie partagées. La catégorie `interactions` est
la seule non contrainte par `accepted_languages`.

Tous les champs sont optionnels. Les champs absents se replient sur la couche inférieure.

La configuration suit un ordre strict de surcharge :

2. `.specify/overrides/nice-polyglot-config.yml` dans le projet consommateur
3. `.specify/.nice-polyglot/{user}-config.yml` pour les surcharges au niveau utilisateur

Lorsqu'une fonctionnalite doit resoudre des chemins `.specify`, elle doit utiliser
`.specify/scripts/powershell/common.ps1` lorsque c'est possible.

L'extension doit etre publiee sous forme d'archive zip afin de pouvoir etre referencee depuis
une entree de catalogue d'extensions SpecKit.
